<h1 align="center">Hermes Channels</h1>

<p align="center"><strong>Slack-style channels where a team of persistent Hermes bots works together — with a human in the loop.</strong></p>

> [!WARNING]
> **Work in progress.** Hermes Channels is under active development: expect rough
> edges, breaking changes, and database migrations between updates. Feedback
> and issues are very welcome.

Hermes Channels is a plugin for [Hermes Agent](https://nousresearch.com) that turns your local Hermes profiles into a team of named bots with their own models, SOULs, skills, and projects, collaborating in channels and threads on your machine. Hermes remains authoritative for every profile's configuration, credentials, memory, and sessions — the plugin adds the shared workspace on top.

- **Home** — an operational center: workspace status, live bot turns (with Stop), workspace cards, recent activity.
- **Channels** — the main workspaces. Mention bots, scope messages to Hermes projects, read Markdown-rendered replies, branch into threads.
- **Bot Management** — build and tune bots: identity, avatars (uploaded, palette, or generated by Hermes image generation — pick the image model and optionally your own prompt), a mythological name generator, SOUL, model and behavior with catalog-backed provider/model dropdowns, skills, workspace — all backed by real Hermes profiles.
- **Session console** — jump from any bot turn into the underlying Hermes session and work with the bot hands-on, without leaving the workspace.

Compatibility floor: **Hermes Agent 0.20.0**; tracked against current
`hermes-agent` main. Desktop shells older than mid-2026 use the default
`standalone` install layout; newer shells support the unified single-folder
layout (`scripts/install.py --layout unified`). Both supported hosts ship
from one codebase: the native Hermes Desktop app and the Hermes web
dashboard. Upgrading from **hermes-crew**? The installer migrates
automatically: legacy bundles and config entries are removed and an existing
`crew/crew.db` workspace is adopted as `channels/channels.db`.

## Quickstart

```bash
git clone https://github.com/goktugvatandas/hermes-channels.git && cd hermes-channels
npm install && npm run build
python scripts/install.py     # installs into $HERMES_HOME (default ~/.hermes)
```

Restart Hermes (Desktop app or `hermes dashboard`), enable the **Hermes Channels**
plugin, and open the **CHANNELS tab**. First run walks you through picking
a default responder and creates **#general**; mention a bot to put it to
work, or open **Bot Management** to name your bots, generate avatars, and pick
models.

## Install

Prerequisites: Node 22.22+, Python 3.11+, Hermes Agent 0.20.0.

```bash
npm install
npm run build
npm run verify:dist
python scripts/install.py
```

`HERMES_HOME` selects the owner profile (default `~/.hermes`). The installer copies:

| Artifact | Destination | Purpose |
| --- | --- | --- |
| `dist/desktop-plugins/hermes-channels/plugin.js` | `$HERMES_HOME/desktop-plugins/hermes-channels/` | Hermes Desktop plugin (self-contained ESM bundle with inlined scoped styles) |
| `dist/plugins/hermes-channels/` | `$HERMES_HOME/plugins/hermes-channels/` | Python backend + web dashboard bundle |
| `dist/skills/hermes-channels/` | `$HERMES_HOME/skills/hermes-channels/` | The `channel-collaboration` agent skill |

Restart or reload Hermes, enable **Hermes Channels**, then open the **CHANNELS tab**. First run creates `#general` with your profiles as members and one default responder.

Upgrades are idempotent: rebuild and rerun the installer; `channels/channels.db` is preserved and schema migrations run automatically.

```bash
# Remove installed code, preserve channel data
python scripts/install.py --uninstall

# Remove installed code and channel data
python scripts/install.py --uninstall --purge-data
```

## Using Channels

### Talking to bots

Messages route deterministically — no hidden magic:

- The channel's **default responder** answers untagged messages.
- `@name` mentions (autocomplete with avatars, anywhere in the draft) route to those members; `@all` notifies everyone.
- Members respond per their **activation policy**: `always`, `mentioned`, `observer`, or `disabled`.
- An optional per-channel **classifier** (off by default) can suggest recipients for ambiguous messages.

The composer supports `/` commands: `/all`, `/inherit` `/global` `/project` (message scope), `/profile` `/search` (navigation), `/clear`.

### Threads and reply placement

Bot answers land where the question was asked: channel-level questions get channel-level answers, thread questions stay threaded. Bots can override this per response (`placement` in the intent envelope): a long work log can stream into a thread while the final result posts to the channel. Humans choose the same way — the channel composer posts to the channel, the thread pane's composer stays in the thread.

### Projects and scope

A channel can default to a Hermes project; a single message can attach one without changing the channel; threads inherit the message's project with isolated per-profile session bindings. Channel scoping narrows routing only — actual filesystem access and approval enforcement remain with Hermes execution controls.

### Bot-to-bot collaboration

Every bot response ends with a hidden intent envelope (`inform`, `result`, `question`, `handoff`, `review_request`, `blocked`, `approval_request`, …) that drives routing. Automated chains are bounded: depth limits, pair-repeat limits, and automated-turn budgets are enforced along the causal chain of turns, and any human message resets the budget. The bundled **channel-collaboration** skill teaches bots the full contract.

### Hands-on sessions

Every bot turn records its Hermes session. **Open session** (on activity
entries, their ⋯ menus, and bot messages' ⋯ Activity section) opens the
native session view in-app on both hosts: the web dashboard resumes it in its
chat, Hermes Desktop routes straight to the session. The embedded **session
console** (⋯ → "Open console") stays available for working without
leaving the workspace: full transcript with channel context folded, live
streaming continuation over the gateway, and Stop support.

## Sessions and projects

Every bot turn runs a real Hermes session **under that bot's own
profile**, scoped to the resolved project of the triggering message (message
scope → thread scope → channel default) — scope a message to a project and
the bot works inside it. These worker sessions are internal plumbing, so
the plugin keeps them out of your way: they are created with the host's internal
session source and archived when the turn finishes, which hides them from the
session sidebar, the command palette, and per-profile chat lists while
keeping every "Open session" button working (those resolve sessions
by id).

## The Channels tab and Bot Mode

Channels lives in a dedicated **CHANNELS tab** beside SESSIONS in the Hermes
Desktop sidebar — focused sections for channels with unread badges, the bot
roster, and Settings, keeping the session list clean.

Channels coexists with [Hermes Bot Mode](https://github.com/NousResearch/Hermes-Bot-Mode)
by design: both present the same Hermes profiles, so your bots show up in
both automatically. Bot chats act as the direct-message surface — clicking a
bot in the CHANNELS tab opens its chat (resuming the latest conversation on
hosts that support it), avatars saved here are mirrored into the profile
asset store so both UIs show the same face, and channel worker sessions
never pollute a bot's chat preview.

## Channels as a messaging platform

The plugin registers a Hermes messaging platform (`channels`), which makes
channels first-class send targets across the whole host — no core patches:

- **Bots anywhere can post into channels**: the standard `send_message`
  tool accepts `channels:<channel>`, so a bot working in any ordinary Hermes
  session can drop results into a channel (and wake its members).
- **CLI**: `hermes send --to channels:general "ship it"`.
- **Cron**: `deliver=channels` jobs route to `CHANNELS_HOME_CHANNEL`.
- The platform appears on the host's Channels settings page, and channels
  are listed in the channel directory when a gateway is running.

Messages arriving through this door are recorded as user-authored (like any
bridge platform treats remote senders) and run through the exact routing
pipeline the composer uses — mentions and routing budgets all apply.

## Data, recovery, and upgrades

Coordination data lives at `$HERMES_HOME/channels/channels.db` (SQLite, WAL). Back up `channels.db` with its `-wal`/`-shm` siblings while Hermes is stopped, or use SQLite backup tooling. Bot sessions and profile state remain in Hermes. Runtime errors appear in Hermes logs; the plugin's durable activity journal survives reloads.
